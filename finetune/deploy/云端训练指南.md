# 云端租卡训练指南（AutoDL RTX 4090，本地无显卡走这条路线）

本地不需要任何显卡：**只有训练和评测这两步在云端跑（约 2~3 小时）**，产物下载回本地后，推理部署用 ollama 纯 CPU 即可。

费用预期：RTX 4090 按量约 ¥1.5~2.5/小时，全程（环境 + 训练 + 评测 + 量化 + 下载）3 小时内，**总花费约 ¥5~15**。用完立刻释放实例，不再计费。

前置确认：本地已完成全量数据生成，`finetune/data/sft_train.jsonl` 存在（没有就先跑 README 步骤 1）。

---

## 第 1 步：本地打包训练文件

```bash
cd finetune
python deploy/pack_for_cloud.py
# 产出 finetune/ft_cloud.zip（约几 MB，含 data/ configs/ data_gen/ eval/）
```

## 第 2 步：租一台 4090

1. 注册 [autodl.com](https://www.autodl.com)，充值 ¥20（按量计费，随时可退余额剩下的）
2. 控制台 → 容器实例 → 创建实例：
   - **计费方式**：按量计费
   - **地域**：选一个 RTX 4090 有货的（哪个便宜选哪个）
   - **GPU**：RTX 4090 × 1（24GB 显存）
   - **镜像**：选「基础镜像」→ PyTorch **2.3 + Python 3.11 + CUDA 12.1**（或更高的 2.x 版本均可）
   - **数据盘**：默认 50GB 够用（基座模型 15GB + 训练产物约 20GB）
3. 创建成功后，实例卡片上点 **JupyterLab** 打开，里面新建「终端」执行后续所有命令

## 第 3 步：上传并解压

JupyterLab 左侧文件面板进入 `/root/autodl-tmp`，把 `ft_cloud.zip` 拖拽上传（几 MB，秒传）。然后终端执行：

```bash
cd /root/autodl-tmp
mkdir -p medical-ft
unzip /root/autodl-tmp/ft_cloud.zip -d /root/autodl-tmp/medical-ft
cd medical-ft && ls
# 应看到：configs/  data/  data_gen/  eval/
```

> 目录结构不要改动：训练配置里的相对路径（`dataset_dir: configs` 等）依赖它。

## 第 4 步：安装 LLaMA-Factory

```bash
source /etc/network_turbo        # AutoDL 学术加速（pip/git 提速）
cd /root/autodl-tmp
git clone --depth 1 --branch v0.9.5 https://github.com/hiyouga/LlamaFactory.git
cd LLaMA-Factory
pip install -e .
pip install -r requirements/metrics.txt
llamafactory-cli --version       # 能打印版本即成功
```

## 第 5 步：下载基座模型（内网免流量费）

训练配置已开启 `use_modelscope: true`，**首次训练会自动下载** Qwen2.5-7B-Instruct（约 15GB，AutoDL 到 ModelScope 走内网，几分钟）。想手动预下载也可以：

```bash
pip install modelscope
modelscope download --model Qwen/Qwen2.5-7B-Instruct --local_dir /root/autodl-tmp/Qwen2.5-7B-Instruct
# 手动下载后，把 configs/qwen2.5-7b-qlora-sft.yaml 的
# model_name_or_path 改为 /root/autodl-tmp/Qwen2.5-7B-Instruct（use_modelscope 可改 false）
```

## 第 6 步：启动训练（约 1~1.5 小时）

```bash
cd /root/autodl-tmp/medical-ft
pip install -r requirements.txt  # eval/run_eval.py 需要 openai 等独立依赖
nohup llamafactory-cli train configs/qwen2.5-7b-qlora-sft.yaml > train.log 2>&1 &
tail -f train.log        # Ctrl+C 退出查看不影响训练（nohup 已后台运行）
```

看什么：
- `train_loss` 应稳定下降（1.5 → 0.8 左右属正常区间）
- 每 100 步的 `eval_loss`：持续回升说明过拟合，可提前停（loss 稳定就行，练手不必纠结）
- 网页断开没关系，`nohup` 在后台跑；重连后 `tail -f train.log` 继续
- 训练产物（LoRA 权重）在 `medical-ft/saves/qwen2.5-7b-qlora-sft/`

## 第 7 步：合并 LoRA + 云端评测

训练完（`train.log` 出现 `training completed`）：

```bash
cd /root/autodl-tmp/medical-ft
llamafactory-cli export configs/merge_export.yaml
# → medical-ft/models/qwen2.5-7b-medical-sft/（完整权重，约 15GB）

pip install vllm
nohup vllm serve models/qwen2.5-7b-medical-sft \
  --served-model-name ft --port 8000 --max-model-len 4096 > vllm.log 2>&1 &
# 等 vllm.log 出现 "Application startup complete"

python eval/run_eval.py --base-url http://localhost:8000/v1 --model ft --api-key empty
# 三套评测约 10 分钟 → eval/reports/report_ft.md
```

达标参考：事实核查 ≥80%、行为规范 ≥95%、NER F1 ≥85%。想对比基座，再 `vllm serve Qwen/Qwen2.5-7B-Instruct` 跑一遍同款评测。

**记得把 `eval/reports/report_ft.md` 和 `train.log` 留存下载。**

## 第 8 步：转 GGUF 量化（云端做，只回传 4.7GB）

```bash
source /etc/network_turbo
cd /root/autodl-tmp
git clone https://github.com/ggerganov/llama.cpp
pip install -r llama.cpp/requirements.txt
python llama.cpp/convert_hf_to_gguf.py medical-ft/models/qwen2.5-7b-medical-sft \
  --outfile qwen2.5-7b-medical-sft-f16.gguf

apt update && apt install -y cmake build-essential   # 需 root，容器默认即是
cd llama.cpp && cmake -B build && cmake --build build --config Release -j
./build/bin/llama-quantize /root/autodl-tmp/qwen2.5-7b-medical-sft-f16.gguf \
  /root/autodl-tmp/qwen2.5-7b-medical-sft-q4_k_m.gguf Q4_K_M
```

产出 `qwen2.5-7b-medical-sft-q4_k_m.gguf`（约 4.7GB）。

## 第 9 步：下载产物 → 释放实例

下载方式（任选）：

- **scp**（推荐，快）：实例卡片有 SSH 登录指令，在**本地**终端执行：
  ```bash
  scp -P <端口> root@<实例地址>:/root/autodl-tmp/qwen2.5-7b-medical-sft-q4_k_m.gguf D:/models/
  ```
- JupyterLab 文件面板右键下载（大文件较慢）

**下载清单**：`qwen2.5-7b-medical-sft-q4_k_m.gguf`（必需）、`eval/reports/report_ft.md`、`train.log`（可选）。

确认下载完整后，控制台 **「释放实例」**（只关机会保留磁盘收少量存储费；确认不再用就彻底释放）。

## 第 10 步：回到本地部署

按 [deploy/接入说明.md](接入说明.md) 路线 A 继续：把 GGUF 放到 `finetune/deploy/`，`ollama create` → 改 `backend/.env` 三行 → 重启后端 → 前端实测。推理纯 CPU 可跑（Q4 7B 约每秒 5~10 字）。

## 常见问题

| 现象 | 处理 |
|---|---|
| 训练 OOM | 确认 YAML 里 `quantization_bit: 4` 未被注释；仍 OOM 则 `per_device_train_batch_size: 1` 且 `gradient_accumulation_steps: 16` |
| pip/git 慢或超时 | `source /etc/network_turbo`；或 `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple ...` |
| bitsandbytes 报错（云上一般不会） | 注释 YAML 的 `quantization_bit: 4` 改纯 bf16 LoRA，4090 24GB 够 |
| 训练中断（实例故障等） | `saves/` 里有每 100 步的 checkpoint；使用 `llamafactory-cli train configs/qwen2.5-7b-qlora-sft.yaml resume_from_checkpoint=saves/qwen2.5-7b-qlora-sft/checkpoint-<step>` 显式续训 |
| vllm serve 起不来 | 看 `vllm.log` 末尾；常见是端口占用，换 `--port 8001` |
| 下一步想提高效果 | 回本地后从 PG `consultations` 导出真实对话脱敏再做第二轮（见 README「注意事项」） |
